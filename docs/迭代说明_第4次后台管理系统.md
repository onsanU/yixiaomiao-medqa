## 一、本次迭代目标

医小喵此前只有面向用户的聊天问答界面，**对话记录、用户数据、系统状态都只能命令行查看**，缺少管理视角。本次迭代引入开源后台模板 **AdminLTE v4.9.1（MIT）**，以**前后端分离**形态为医小喵搭建独立管理后台（`/admin`）：

1. **数据看板**：累计问答数 / 用户数 / 今日问答 / 知识块数一屏总览，近 14 天问答趋势 + 功能类型分布图表、热门健康主题 TOP10、最新对话
2. **对话记录管理**：分页浏览 + 按用户 / 关键词 / 类型（问答 / 看图解读 / 护理计划 / 猫咖对话）三重筛选，详情弹窗看完整回答与依据来源，支持单条删除与按用户清空
3. **用户统计**：全部用户按问答数排序，含使用功能徽标、首次/最近活跃时间，一键跳转查看该用户记录
4. **系统状态**：Ollama 大模型列表、SenseVoice ASR 语音服务、问答数据库、医疗知识库（27 篇资料 / 751 知识块）实时状态监控

设计约束：**主聊天界面零改动**；后台资源全本地化（零外网 CDN 依赖，断网可用）；管理 API 独立模块，不侵入主业务路由。

## 二、完成内容

### 1. 🎨 AdminLTE 模板选型与本地化（`app/static/admin/vendor/`）
- 选型理由：医小喵前端是纯静态（无 npm 构建链），AdminLTE v4 恰好是 Bootstrap 5.3 + 原生 JS 的**纯静态模板**，可直接嵌入 FastAPI 静态托管，无需引入整套 React 工程（SecureShop 的 React 后台因此不适用医小喵）
- 资源清单（共 864KB，npm `admin-lte@4` 经 npmmirror 安装后拷贝 dist）：
  - `adminlte.min.css / adminlte.min.js`（官方 dist，CSS 已内含 Bootstrap 样式、无任何外部 url 引用）
  - `bootstrap.bundle.min.js`（Bootstrap 5.3.8 交互组件）
  - `bootstrap-icons`（图标字体，css 与 fonts 同层放置修正相对路径）
  - `overlayscrollbars`（侧栏滚动条，可选增强）
- 图表用医小喵已有的 `ECharts`（不引入模板默认的 apexcharts，少一个包袱）

### 2. 🔌 管理 API 模块（`app/admin_api.py`，独立 router，`main.py` 仅注册 2 行）
| 接口 | 说明 |
|------|------|
| `GET /admin/api/stats` | 看板统计：总量 / 用户数 / 今日 / 人均 / 近14天趋势 / 类型分布 / 主题分布 / 知识库块数 |
| `GET /admin/api/records` | 对话记录分页（page/size + user/kw/type 筛选） |
| `GET /admin/api/records/{id}` | 单条完整记录（含全文回答 + 来源依据） |
| `DELETE /admin/api/records/{id}` | 删除单条记录 |
| `DELETE /admin/api/records?user=` | 清空某用户全部记录 |
| `GET /admin/api/users` | 用户聚合统计（问答数 / 首末活跃 / 功能类型） |
| `GET /admin/api/system` | 系统状态（Ollama 模型 / ASR 健康 / DB / 知识库） |

要点：
- 记录**类型自动识别**：`[📷图片]` 前缀 → 看图解读；`[📋计划]` 前缀 → 护理计划；`猫咖-*` 用户 → 猫咖对话；其余 → 问答（与 main.py 历史存储约定一致）
- **主题归类延迟 import**（`from app.main import TOPIC_KEYWORDS` 在函数内），与主程序保持单一数据源、避免循环依赖
- 系统状态接口**优雅降级**：Ollama / ASR 未启动时返回 `ok:false` + 提示文案，不影响其他数据

### 3. 🖥️ 管理前端页面（`app/static/admin/`，AdminLTE 布局 4 页）
- `index.html` 数据看板：4 张统计卡片（AdminLTE small-box）+ ECharts 近14天趋势面积图 / 类型环形图 + 热门主题 TOP10 进度条（青蓝渐变）+ 最新 5 条对话
- `records.html` 对话记录：筛选表单（昵称/关键词/类型下拉）+ 服务端分页表格 + 详情 Modal（完整回答 + 📚 依据来源徽标）+ 单条删除（confirm 确认）
- `users.html` 用户统计：聚合表格 + 功能徽标；「记录」按钮带 `?user=` 参数跳转记录页自动筛选；清空按钮按用户删除
- `system.html` 系统状态：Ollama 模型表格（名称/大小）· ASR 状态 · DB 概况 · 知识库 27篇/751块 · 手动刷新
- 所有页面通过 `fetch('/admin/api/*')` 同源取数，经 FastAPI 根静态挂载托管，访问入口 `http://localhost:8000/admin/`

## 四、遇到的问题与解决

| 问题 | 解决方案 |
|------|---------|
| web_extract 无法提取 GitHub 内容（ddgs 后端限制） | 改用浏览器打开 + console 提取 README / 页面资源引用清单 |
| admin-lte npm 包只含编译产物不含 demo 页面，无法照抄官方 HTML | 浏览器打开 adminlte.io/themes/v4 live demo，console 抓取真实资源引用列表（图标= Bootstrap Icons、滚动条= OverlayScrollbars、图表= apexcharts） |
| 大陆网络 CDN 不可达（jsdelivr 等） | 全部资源 npmmirror 安装后本地化拷贝进 `vendor/`；grep 校验 css/js 无任何外部 url 引用 |
| bootstrap-icons 的 css 内 `url("fonts/...")` 相对路径，css 与 fonts 不同层会 404 | css 移到与 fonts 同级目录（`vendor/bootstrap-icons/` 下） |
| 图表库选型 | 不引 apexcharts，复用医小喵已有本地 `echarts.min.js`（/echarts.min.js 绝对路径引用） |
| 新版 FastAPI include_router 路由静态检查困难 | 不纠结路由树结构，直接启动服务 curl 实测 7 个接口 |
| 知识块数在 stats 与 system 重复实现 | 抽公共函数 `_kb_files() / _kb_chunks()`（读 Chroma collection count） |
| 类型徽标颜色映射写绕（先找中文再反查代码） | 后端 users 同时返回 `types`（代码）与 `type_labels`（中文），前端直接用 types 映射颜色 |
