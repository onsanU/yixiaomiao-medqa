# 迭代说明 · 第2次迭代

| 项目 | 内容 |
|------|------|
| 项目名称 | 医疗健康智能问答助手（医小喵） |
| 迭代时间 | 2026-08-14（下午） |
| 迭代类型 | 功能增强 + 全量测试 |
| 参与角色 | 咪咪（AI辅助）+ 主人 |

---

## 一、本次迭代目标

在环节⑤⑥基础上增强用户体验与数据管理：
1. **用户区分**：多位使用者各自独立的历史记录与个性化推荐
2. **历史详情 + 继续追问**：点击历史记录查看完整问答，并支持基于上文的多轮追问
3. **全量测试**：对 27 个知识主题病症问题 + 特殊边界问题进行全面测试并记录

## 二、完成内容

1. **用户系统**：首次访问输入昵称（存 localStorage），问答历史按昵称隔离存储（SQLite 增加 user 字段），个性化推荐按用户独立统计，清空历史只清当前用户
2. **历史详情查看**：点击历史面板条目 → 弹出对话详情（完整问题/完整回答/参考来源/时间）
3. **继续追问（多轮对话）**：详情弹窗可继续提问，携带上文上下文（history 参数 → ChatOllama messages），大厨能理解"那能吃什么药吗"这类指代性追问
4. **全量测试**：32 题测试数据集（27 主题病症 + 防幻觉/诊断边界/处方边界/无关问题），自动评价 + 测试记录存档

## 三、测试数据

详见 `docs/测试记录_第2次迭代.md`（全量 32 题逐条记录）。

**汇总：通过 31 / 待检查 1 / 异常 0（共 32 题）**
- 27 个知识主题病症问题：全部通过 ✅
- 防幻觉（火星种土豆 / 量子力学）：如实回答"资料库中暂无相关内容" ✅
- 诊断边界（是否肺癌）：未下诊断，说明咳嗽原因多样并建议就医 ✅
- 处方边界（要求开药）：未直接开药，提示需医生判断 ✅
- 无关问题（今天天气）：1 题待检查（回答未编造天气，仅做语境分析，可接受）

## 四、遇到的问题与解决

| 问题 | 解决方案 |
|------|---------|
| 历史接口 sources 字段返回字符串而非数组，前端 join 报错 | db.py 读取时 json.loads 解析回列表 |
| 中文昵称在 curl 测试中未编码导致请求失败 | 前端用 encodeURIComponent 编码（页面无此问题） |
| 旧数据无 user 字段 | 建表时 PRAGMA 检查列，缺失则 ALTER TABLE 补列，旧记录归入"游客" |

**成果**：多用户隔离 + 多轮追问 + 全量测试报告，系统可用性和可交付性显著提升。
